# Поэтапный процесс настройки Allure отчетов с историей

Этот документ описывает шаги, необходимые для корректной генерации Allure отчетов с сохранением истории предыдущих запусков.

## Шаг 1: Первый запуск и создание "базового" отчета

**Цель:** Сгенерировать первый Allure отчет, который послужит основой для дальнейшего отслеживания истории. На этом этапе история еще не будет отображаться, так как нет предыдущих данных для сравнения.

**Действия:**

1.  **Очистка рабочего пространства (для чистоты эксперимента):**
    ```bash
    rm -rf allure-results
    rm -rf allure-report
    ```

2.  **Запуск тестов:**
    ```bash
    xcodebuild test \
      -project "Demo App.xcodeproj" \
      -scheme "Demo App" \
      -destination "platform=iOS Simulator,name=iPhone 15 Pro,OS=17.0"
    ```
    *Это создаст директорию `allure-results` с результатами текущего запуска.*

3.  **Генерация первого Allure отчета:**
    ```bash
    allure generate allure-results -o allure-report
    ```
    *После выполнения этой команды в `allure-report` появится поддиректория `history`, которая будет использоваться для следующих запусков.*

4.  **Проверка отчета:**
    ```bash
    allure open allure-report
    ```
    *Убедитесь, что отчет открылся. Разделы "Trends" и "Timeline" будут пустыми или неактивными, что является ожидаемым поведением для первого запуска.*

## Шаг 2: Последующие запуски с сохранением истории

**Цель:** Сгенерировать новый Allure отчет, который будет включать историю предыдущих запусков.

**Действия:**

1.  **Запустите тесты (повторно):**
    ```bash
    xcodebuild test \
      -project "Demo App.xcodeproj" \
      -scheme "Demo App" \
      -destination "platform=iOS Simulator,name=iPhone 15 Pro,OS=17.0"
    ```
    *Это обновит или создаст новые файлы результатов в `allure-results`.*

2.  **Сгенерируйте новый Allure отчет:**
    ```bash
    allure generate allure-results -o allure-report
    ```
    *Allure CLI автоматически найдет папку `history` в существующей директории `allure-report`, использует ее для построения трендов и обновит ее новыми данными.*

4.  **Проверка отчета:**
    ```bash
    allure open allure-report
    ```
    *Теперь в отчете должны отображаться тренды и история на соответствующих вкладках, сравнивающие текущий запуск с предыдущим.*

## Шаг 3: Автоматизация в CI/CD (концептуально)

Для автоматизации этого процесса в CI/CD пайплайне (например, GitHub Actions):

1.  **Сохраняйте всю папку `allure-report` как артефакт** после каждого успешного запуска.
2.  **Загружайте этот артефакт** на следующем запуске пайплайна перед генерацией нового отчета.
3.  **Генерируйте новый отчет** командой `allure generate allure-results -o allure-report`. Allure сам найдет историю в существующей папке.

---

Таким образом, ключевым моментом является сохранение и передача папки `allure-report` между запусками. Allure CLI автоматически подхватывает из нее историю.

---
**Важно:** Флаг `--clean` принудительно удаляет предыдущий отчет, включая историю. Используйте его, только если хотите начать историю заново.
