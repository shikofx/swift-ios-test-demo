= Анализ метрик и визуализация в Allure
:sectnums:
:source-highlighter: highlight.js

Allure — это не просто "смотрелка" для отчетов, а мощный аналитический инструмент. Он помогает отвечать на важные вопросы о качестве продукта и стабильности тестов. Рассмотрим, какие метрики можно анализировать.

== Ключевые метрики на главной странице (Overview)

Главный дашборд предоставляет быстрый срез по состоянию последнего запуска:

*   **Статистика по статусам (Statuses):** Классический виджет, показывающий соотношение пройденных, упавших, сломанных и пропущенных тестов. Помогает моментально оценить общее здоровье сборки.
*   **Тренд выполнения (Trend):** Один из самых важных виджетов. Показывает, как менялось количество тестов и их статусы от сборки к сборке. Растущий "красный" сектор — явный сигнал о проблемах.
*   **Длительность выполнения (Duration):** Показывает, сколько времени занял каждый тест. Помогает выявлять аномально долгие тесты, которые замедляют CI.
*   **Распределение по приоритетам (Severities):** Если вы используете метки приоритетов (Blocker, Critical, Normal), этот виджет покажет, сколько тестов каждого уровня упало. Помогает сфокусироваться на самых критичных проблемах.

== Глубокий анализ с помощью вкладок

Для детального исследования Allure предлагает несколько специализированных вкладок.

=== Categories (Категории дефектов)

Это мощнейший инструмент для triage (анализа) упавших тестов. Вы можете настроить правила, по которым Allure будет автоматически распределять падения на:

*   **Product Defects:** Ошибки в приложении. Тесты упали, потому что функциональность сломана.
*   **Test Defects:** Ошибки в самих тестах. Например, нестабильный локатор, неверные ожидания, проблемы с тестовыми данными.

Эта категоризация позволяет быстро понять, кому адресовать проблему: разработчикам или команде автоматизации.

=== Graphs (Графики)

Эта вкладка визуализирует данные по всему тестовому набору. Здесь можно увидеть распределение тестов по:
*   **Статусу:** Наглядная диаграмма общего состояния.
*   **Длительности:** Помогает найти "тяжелые" тестовые наборы.
*   **Приоритету (Severity):** Показывает, насколько хорошо покрыты тестами критичные части функциональности.

=== Timeline (Временная шкала)

Эта вкладка показывает, как тесты выполнялись во времени. Она незаменима для анализа:
*   **Производительности:** Можно увидеть, какие тесты выполняются дольше всего и являются "бутылочным горлышком".
*   **Параллелизации:** Если тесты запускаются в несколько потоков, Timeline покажет, насколько эффективно загружены ресурсы. Можно выявить тесты, которые блокируют выполнение других.

Анализируя эти метрики в комплексе, команда может принимать взвешенные решения о качестве продукта, стабильности тестового покрытия и оптимизации CI/CD процессов.
