== 3. Front Matter: Метаданные страниц

**Front Matter** — это специальный блок в формате YAML, который размещается в самом начале файла (например, `.md` или `.adoc`). Он заключается между двумя тройными дефисами (`---`) и позволяет задавать переменные и метаданные для конкретной страницы.

Jekyll читает этот блок и использует его для генерации страницы.

=== Пример Front Matter

[source,yaml]
----
---
layout: default
title: Моя первая страница
author: Дмитрий
published: true
---
== {{ page.title }}

Эта страница была написана автором: *{{ page.author }}*.
----

=== Предопределенные переменные

Некоторые переменные имеют специальное значение для Jekyll и тем:

*   `layout`: Указывает, какой макет из папки `_layouts` использовать для этой страницы.
*   `title`: Заголовок страницы, который часто используется в теге `<title>` и в заголовках `<h1>`.
*   `permalink`: Позволяет переопределить URL страницы. Например: `/about/`.
*   `published`: Если установлено в `false`, Jekyll не будет генерировать эту страницу.

=== Пользовательские переменные

Вы можете определять любые свои переменные (как `author` в примере выше) и затем использовать их в любом месте страницы или в макете через объект `page` (например, `{{ page.author }}`). Это делает страницы очень гибкими и позволяет легко управлять контентом.

=== Практический пример: Динамическая генерация Front Matter в CI

Front Matter особенно полезен, когда его генерируют автоматически. В нашем проекте мы используем shell-скрипт в GitHub Actions для создания страницы отчета SwiftLint. Этот скрипт динамически формирует Front Matter.

Рассмотрим ключевые части скрипта:

[source,bash]
----
# 1. Вычисляем summary с помощью утилиты jq
TOTAL_FILES=$(jq '[.[] | .file] | unique | length' $JSON_FILE)
TOTAL_WARNINGS=$(jq '[.[] | select(.severity=="Warning")] | length' $JSON_FILE)
TOTAL_ERRORS=$(jq '[.[] | select(.severity=="Error")] | length' $JSON_FILE)

# 2. Генерируем Front Matter с помощью `cat` и `HEREDOC`
cat <<EOF > $MD_FILE
---
layout: default
title: SwiftLint Style Report
total_files: $TOTAL_FILES
total_warnings: $TOTAL_WARNINGS
total_errors: $TOTAL_ERRORS
violations:
EOF

# 3. Добавляем список нарушений в Front Matter
jq '.[] | @json' $JSON_FILE | sed 's/^/  - /' >> $MD_FILE
----

==== Что здесь происходит?

В этом скрипте `$JSON_FILE` и `$MD_FILE` — это shell-переменные, которые получают свои значения из входных параметров (`inputs`) GitHub Action.

*В файле `action.yml` мы определяем `inputs`:*
[source,yaml]
----
inputs:
  output-path:
    description: '...'
----

*А в файле workflow `deploy-github-pages.yml` мы передаем значение в этот `input`:*
[source,yaml]
----
uses: ./.source/.github/actions/create-swiftlint-report-page
with:
  output-path: .site/swiftlint-report.md
----

Таким образом, внутри скрипта переменная `$MD_FILE` действительно будет равна `.site/swiftlint-report.md`.

---

1.  **Вычисление значений**: С помощью утилиты `jq` мы парсим JSON-отчет и вычисляем необходимые метрики (количество файлов, предупреждений, ошибок). Эти значения сохраняются в shell-переменные (`$TOTAL_FILES`, `$TOTAL_WARNINGS`, `$TOTAL_ERRORS`).

2.  **Создание Front Matter**: Команда `cat <<EOF > $MD_FILE` создает Markdown-файл и записывает в него блок `Front Matter`. Внутри этого блока мы вставляем вычисленные значения прямо из shell-переменных. Давайте разберем эту строку подробнее:
*   `cat`: Стандартная команда для вывода содержимого. В данном случае она используется для записи текста в файл.
*   `<<EOF`: Это специальный синтаксис, называемый **"Here Document"** (или "heredoc"). Он говорит shell-интерпретатору: "Все, что идет дальше, до строки, содержащей только `EOF`, является входными данными для команды `cat`". Важно, что когда `EOF` указан без кавычек, shell **выполняет подстановку переменных** (например, `$TOTAL_FILES` заменяется на свое значение).
*   `<<'EOF'`: Если же ограничитель `EOF` заключен в кавычки (как во второй части нашего скрипта), shell обрабатывает текст **буквально**, не пытаясь подставить значения переменных. Это необходимо для того, чтобы Liquid-код (например, `{{ page.total_files }}`) дошел до Jekyll в неизменном виде.
*   `EOF`: Это просто маркер (или "ограничитель"), который вы выбираете сами. Он обозначает начало и конец блока текста. `EOF` — это общепринятое соглашение (сокращение от "End Of File"), но можно использовать любое другое слово.
*   `> $MD_FILE`: Это оператор перенаправления вывода. Он берет все, что вывела команда `cat` (а это весь наш текстовый блок), и записывает в файл, путь к которому хранится в переменной `$MD_FILE`. Знак `>` означает, что файл будет перезаписан, если он уже существует.

3.  **Добавление списка**: Команда `jq ... | sed ... >> $MD_FILE` преобразует JSON-массив нарушений в YAML-список и **добавляет** (`>>`) его в конец файла, завершая формирование переменной `violations` в `Front Matter`.

В результате Jekyll получает готовую страницу с таким `Front Matter`:

[source,yaml]
----
---
layout: default
title: SwiftLint Style Report
total_files: 34
total_warnings: 499
total_errors: 119
violations:
  - "{\"file\":\"...\",\"line\":20,...}"
  - "{\"file\":\"...\",\"line\":23,...}"
---
----

После этого в шаблоне страницы мы можем легко получить доступ к этим данным через `{{ page.total_files }}`, `{{ page.total_warnings }}` и так далее, чтобы отобразить их в таблице.
