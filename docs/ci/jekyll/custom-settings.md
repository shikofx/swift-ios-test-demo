 # Использование Jekyll с GitHub Actions

Когда вы создаете сайт Jekyll с помощью GitHub Pages, Jekyll запускается в среде, ограниченной по соображениям безопасности, но содержащей множество плагинов и тем из белого списка, чтобы упростить настройку сайта.

Единственным обходным путем, позволяющим контролировать среду сборки и набор гемов, но при этом использовать GitHub Pages для хостинга сайта, ранее была сборка в другом месте и отправка содержимого собранного каталога в ветку `gh-pages` вашего репозитория.

Однако теперь GitHub предоставляет вам возможность использовать свой внутренний продукт CI/CD под названием GitHub Actions для сборки и развертывания (хостинга) вашего сайта Jekyll с полным контролем над средой сборки и набором гемов.

## Преимущества использования Actions

### Контроль над набором гемов

*   **Версия Jekyll** — Вместо использования классической версии, предоставляемой GitHub Pages и указанной в списке версий зависимостей, вы можете использовать любую версию Jekyll, какую захотите. Например, 4.4.1, или указать прямо на репозиторий через `Gemfile`.
*   **Плагины** — Вы можете использовать любые плагины Jekyll, независимо от того, находятся ли они в белом списке GitHub, включая любые файлы `*.rb`, размещенные в каталоге `_plugins` вашего сайта.
*   **Темы** — Хотя использование пользовательской темы возможно и без Actions, теперь возможно использовать темы, зависящие от функций, представленных в новых версиях Jekyll.

Если вы переходите с классического потока, но хотите продолжать использовать тему, размещенную на GitHub, вы можете использовать плагин `jekyll-remote-theme`, добавить все необходимые зависимости вашей темы (ранее поставлявшиеся по умолчанию) в `_config.yml` и `Gemfile` и правильно установить слаг репозитория темы `remote_theme: <owner>/<repo_name>` в вашем `_config.yml`.

### Управление рабочим процессом

*   **Кастомизация** — Создавая файл рабочего процесса для запуска Actions, вы можете указывать пользовательские шаги сборки, использовать переменные окружения.
*   **Логирование** — Лог сборки виден и может быть настроен на подробный вывод, что значительно упрощает отладку ошибок с помощью Actions.
*   **Кэширование** — Действие `ruby/setup-ruby` позволяет автоматически кэшировать установленные гемы вместо того, чтобы загружать бандл при каждой сборке.

## Настройка рабочего пространства

Первое и главное требование — это проект Jekyll, размещенный на GitHub. Выберите существующий проект Jekyll или следуйте быстрому старту и отправьте репозиторий на GitHub, если он там еще не размещен.

Сайт Jekyll, который мы будем использовать для оставшейся части этого руководства, изначально состоит только из `_config.yml`, страницы `index.md` и `Gemfile`. Их содержимое соответственно:

```yaml
# _config.yml

title: "Jekyll Actions Demo"
```

```markdown
---
---

Welcome to My Home Page

{% assign date = '2020-04-13T10:20:00Z' %}

- Original date - {{ date }}
- With timeago filter - {{ date | timeago }}
```

```ruby
# Gemfile

source 'https://rubygems.org'

gem "jekyll", "~> 4.2"

group :jekyll_plugins do
  gem "jekyll-timeago", "~> 0.13.1"
end
```

Демо-сайт использует Jekyll 4 и сторонний плагин, оба из которых в настоящее время не входят в белый список для использования на GitHub Pages. Плагин позволит нам описать, как давно была дата от сегодняшнего дня. Например, если мы укажем дату как `2016-03-23T10:20:00Z`, а текущая дата — `2020-04-13T10:20:00Z`, то вывод будет `4 years and 3 weeks ago`.

Действие, которое мы используем, заботится об установке гемов Ruby и зависимостей. Хотя это упрощает настройку для пользователя, могут возникнуть проблемы, если также будет закоммичен `Gemfile.lock`, сгенерированный старой версией Bundler.

## Настройка Action

1.  Перейдите на вкладку **Settings** в вашем репозитории.
2.  Нажмите **Pages** в разделе **Code and automation**.
3.  Измените **Source** в разделе **Build and deployment** с **Deploy from a branch** на **GitHub Actions**.
4.  Перейдите на вкладку **Actions** в вашем репозитории.
5.  Начните **New workflow** и найдите **Jekyll**.
6.  Нажмите **Configure** под рабочим процессом **Jekyll** (не **GitHub Pages Jekyll workflow**).
7.  Просмотрите изменения и нажмите **Commit changes**.

## Сборка и развертывание

При отправке любых локальных изменений в ветку по умолчанию будет запущен Action, и начнется сборка.

Чтобы следить за прогрессом и видеть любые ошибки сборки, проверьте статус сборки одним из следующих способов:

*   **Просмотр по коммиту**
    Перейдите в представление репозитория на GitHub. Под последним коммитом (вверху) вы увидите символ статуса рядом с сообщением коммита в виде галочки или крестика. Наведите на него и нажмите на ссылку **details**.
*   **Вкладка Actions**
    Перейдите на вкладку **Actions** вашего репозитория. Нажмите на вкладку рабочего процесса **jekyll**.

Если все пройдет успешно, все шаги будут зелеными, и собранные ассеты будут загружены на GitHub Pages.

Чтобы увидеть живой сайт, перейдите на вкладку **Deployments** в вашем репозитории и нажмите на URL развернутого сайта.

Когда вам нужно будет внести дальнейшие изменения в сайт, сделайте коммит в ветку по умолчанию и отправьте его. Рабочий процесс снова соберет и развернет ваш сайт.
