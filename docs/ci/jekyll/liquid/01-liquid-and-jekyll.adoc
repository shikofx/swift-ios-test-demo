== 1. Как Jekyll и Liquid работают вместе

Прежде чем погружаться в детали синтаксиса Liquid, важно понять, как он интегрирован в Jekyll и откуда берутся данные для шаблонов.

Liquid не требует специальной конфигурации. Он просто работает "из коробки" в любом файле, который обрабатывает Jekyll (например, `.html`, `.md`, `.adoc`).

Jekyll предоставляет Liquid доступ к данным через предопределенные **объекты**. Вот основные из них:

=== 1. Объект `site`

Содержит глобальные данные вашего сайта. В основном это информация из файла `_config.yml`.

[source,liquid]
----
<h1>{{ site.title }}</h1>
<p>{{ site.description }}</p>
----

=== 2. Объект `page`

Содержит данные, специфичные для текущей страницы. В основном это переменные из **Front Matter** (блок YAML в начале файла).

*Файл `about.md`:*
[source,yaml]
----
---
layout: default
title: О нас
author: Дмитрий
---
== {{ page.title }}

Автор этой страницы: {{ page.author }}.
----

=== 3. Объект `content`

Это специальная переменная, доступная только в файлах макетов (`_layouts`). Она содержит весь отрендеренный HTML-контент страницы, которая использует этот макет.

*Файл `_layouts/default.html`:*
[source,html]
----
<!DOCTYPE html>
<html>
  <body>
    <header>Шапка сайта</header>
    <main>
      {{ content }}
    </main>
    <footer>Подвал сайта</footer>
  </body>
</html>
----

Таким образом, "конфигурация" Liquid — это, по сути, определение данных в `_config.yml` и во Front Matter ваших страниц, которые Jekyll затем передает в шаблонизатор.
