### Новый план развития сайта GitHub Pages

Этот документ описывает поэтапный план по созданию комплексного дашборда для CI/CD на GitHub Pages с использованием темы `Chirpy`. Каждая фаза представляет собой логический блок работ с четкими целями и задачами.

---

### Фаза 1: Фундамент — Новая тема и страница последнего билда

**Цель:** Заменить текущую тему на `Chirpy`, сохранив работоспособность сайта. На этом этапе у нас будет одна главная страница, которая всегда отображает отчет *последнего* завершенного билда.

**Задачи:**

1.  **Интеграция темы `Chirpy`:**
    *   Изучить документацию по `Chirpy` (например, `getting-started.adoc`).
    *   Обновить `_config.yml` и `Gemfile` для использования новой темы.
    *   Создать базовую структуру каталогов, которую требует `Chirpy` (например, `_posts`, `assets/img/favicons`).
    *   Настроить CI-пайплайн для корректной сборки сайта с новой темой.

2.  **Создание шаблона страницы билда:**
    *   Разработать макет (`_layouts/build.html`), который будет служить основой для всех страниц с отчетами.
    *   **Структура макета:**
        *   **Боковая панель (Sidebar):** Информация о билде (номер, ветка, коммит, автор, дата).
        *   **Основной контент:** Вкладки (tabs) для переключения между отчетами:
            *   Вкладка "Allure Report" (будет содержать `<iframe>`).
            *   Вкладка "SwiftLint Report".
            *   Вкладка "SwiftFormat Report".
        *   **Дополнительно:** Секция для скачивания артефактов, связанных с билдом.

3.  **Наполнение данными:**
    *   Модифицировать CI-пайплайн так, чтобы он генерировал один `index.md` в корне сайта.
    *   Этот файл должен использовать макет `build.html` и получать все необходимые данные (номер билда, хэш коммита и т.д.) через `Front Matter`.

**Результат фазы:** Рабочий сайт на теме `Chirpy` с одной страницей, показывающей полный отчет последнего билда.

### Фаза 2: Версионирование — Уникальная страница для каждого билда

**Цель:** Каждая сборка CI должна публиковаться по своему уникальному, постоянному URL. Это позволит сохранять историю и делиться ссылками на конкретные отчеты.

**Задачи:**

1.  **Изменение логики CI:**
    *   В CI-пайплайне генерировать страницы по пути `/<branch_name>/<build_number>/index.md`.
    *   **Важно:** Необходимо "санитизировать" имя ветки, заменяя недопустимые символы (например, `/` на `-`).

2.  **Создание перенаправлений (Redirects):**
    *   Для удобства создать страницы-редиректы:
        *   `/<branch_name>/latest/index.html` -> будет перенаправлять на последний билд в этой ветке.
        *   `/latest/index.html` -> будет перенаправлять на последний билд в `main` ветке.
    *   Это можно реализовать с помощью простого HTML-файла с мета-тегом `refresh`.

**Результат фазы:** Каждый билд доступен по уникальному URL. Появилась возможность отслеживать историю, переходя по ссылкам.

### Фаза 3: Агрегация и навигация — Главный дашборд

**Цель:** Создать главную страницу (`index.html`), которая будет служить центральным хабом для навигации по всем билдам и веткам.

**Задачи:**

1.  **Сбор метаданных:**
    *   На каждом запуске CI генерировать небольшой `build-meta.json` файл, содержащий ключевую информацию о билде: `build_number`, `branch_name`, `commit_sha`, `author`, `timestamp`, `status` (успех/провал), а также summary по тестам и линтерам.
    *   Сохранять этот JSON как артефакт.

2.  **Создание манифеста:**
    *   Создать отдельный CI-workflow (или шаг в существующем), который будет:
        1.  Скачивать с ветки `gh-pages` существующий `builds-manifest.json`.
        2.  Скачивать артефакт `build-meta.json` от текущего билда.
        3.  Добавлять метаданные нового билда в `builds-manifest.json`.
        4.  Загружать обновленный манифест обратно в `gh-pages`.

3.  **Динамическая главная страница:**
    *   Главная страница (`index.html`) будет содержать JavaScript, который:
        1.  Загружает `builds-manifest.json`.
        2.  На основе этих данных динамически строит интерфейс:
            *   **Дашборд ветки `main`:** Отображает ключевые метрики и тренды для основной ветки.
            *   **Список веток:** Группирует билды по веткам, показывает количество билдов и последнюю активность.
            *   **Таблица билдов:** Позволяет фильтровать и сортировать все билды.

**Результат фазы:** Полноценный, интерактивный дашборд, который дает полное представление о состоянии CI/CD в проекте.

### Фаза 4: Интеграция Allure и артефактов

**Цель:** Настроить корректное отображение истории в Allure и предоставить доступ к артефактам проекта.

**Задачи:**

1.  **Настройка истории Allure:**
    *   В CI-пайплайне перед генерацией Allure-отчета для нового билда, скачивать папку `history` из Allure-отчета *предыдущего* билда той же ветки.
    *   Использовать эту папку при генерации нового отчета. Это позволит Allure строить графики трендов.

2.  **Управление артефактами:**
    *   На главной странице дашборда добавить секцию "Артефакты проекта".
    *   Здесь можно разместить ссылки на скачивание:
        *   Последней релизной сборки (`.ipa`/`.app`).
        *   Инструментов для разработки (например, скрипты).
        *   Документации.
    *   CI-пайплайн для релизных сборок должен будет загружать эти артефакты в определенную директорию на `gh-pages`.

**Результат фазы:** Отчеты Allure содержат исторические данные. На сайте доступна для скачивания последняя версия приложения и другие полезные ресурсы.
