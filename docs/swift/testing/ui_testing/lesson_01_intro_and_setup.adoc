== Что такое UI-тестирование?

*UI-тестирование* (User Interface Testing) — это процесс проверки графического интерфейса приложения с целью убедиться, что он работает так, как ожидают пользователи. В контексте iOS мы будем имитировать действия пользователя: нажатия на кнопки, ввод текста, свайпы и так далее.

Согласно нашей тестовой стратегии (`TEST-STRATEGY.adoc`), UI-тесты находятся на вершине пирамиды тестирования. Это означает, что они:

*   **Интеграционные и сквозные (E2E):** Проверяют взаимодействие нескольких компонентов или полный пользовательский сценарий (например, от входа в приложение до совершения покупки).
*   **Реалистичные:** Максимально точно воспроизводят путь пользователя в приложении.
*   **Хрупкие и медленные:** Они требуют больше времени на выполнение и более чувствительны к изменениям в UI, чем Unit-тесты.

Основным инструментом для написания UI-тестов в Xcode является фреймворк `XCUITest`.

== Знакомство с XCUITest

`XCUITest` — это нативный фреймворк от Apple, который позволяет писать тесты для проверки пользовательского интерфейса.

Ключевые компоненты `XCUITest`:

*   `XCUIApplication`: Прокси-объект, представляющий тестируемое приложение. Через него мы запускаем и завершаем приложение.
*   `XCUIElement`: Прокси-объект, представляющий любой элемент на экране (кнопку, текстовое поле, ячейку таблицы).
*   `XCUIElementQuery`: Запрос для поиска одного или нескольких `XCUIElement` на экране.
*   `XCTestCase`: Базовый класс для всех наших тестов.

== Настройка проекта: Добавление UI Test Target

Прежде чем писать тесты, нам нужно добавить в проект специальный таргет (цель сборки).

После создания таргета важно правильно настроить схему запуска тестов. Это позволит нам передавать в приложение специальные параметры и управлять его поведением во время тестирования.

. Откройте менеджер схем: `Product` -> `Scheme` -> `Edit Scheme...` (или `Cmd + <`).

. В левой части окна выберите секцию `Test`.

. На вкладке `Info` убедитесь, что ваш новый UI-тестовый таргет (`swift_ios_test_demoUITests`) включен (отмечен галочкой).

. Перейдите на вкладку `Options`. Здесь рекомендуется включить опцию `Code Coverage` для сбора метрик о покрытии кода тестами.
+
[TIP]
====
*Как проверить, что сбор покрытия включен?*

. Запустите тесты, нажав `Cmd+U`.
. После завершения откройте навигатор отчетов (Report navigator) — последняя иконка на левой панели Xcode.
. Выберите последний тестовый запуск.
. В основной части окна перейдите на вкладку `Coverage`.

Если все настроено правильно, вы увидите отчет по покрытию для вашего приложения. Если вкладка пуста, вернитесь к настройкам схемы и убедитесь, что опция `Code Coverage` активна.
====

. Перейдите на вкладку `Arguments`. Это одна из самых важных настроек для UI-тестирования.
    *   **Arguments Passed On Launch:** Аргументы, которые передаются при запуске приложения. Мы можем использовать их, чтобы приложение "знало", что оно запущено в тестовом режиме. Давайте добавим аргумент `-UITesting`.
    *   **Environment Variables:** Переменные окружения. Они отлично подходят для управления конкретными функциями. Например, мы можем отключить анимации, чтобы тесты выполнялись быстрее и были более стабильными. Добавим переменную `DISABLE_ANIMATIONS` со значением `true`.

Зачем это нужно? В коде основного приложения мы можем проверять эти параметры и менять его поведение. Например, в `AppDelegate` или `SceneDelegate` можно добавить:

[source, swift]
--
// Пример проверки в коде приложения
func scene(_ scene: UIScene, willConnectTo session: UISceneSession, options connectionOptions: UIScene.ConnectionOptions) {
    // ...

    #if DEBUG
    if ProcessInfo.processInfo.arguments.contains("-UITesting") {
        // Если приложение запущено с флагом -UITesting,
        // можно сбросить состояние, подменить данные и т.д.
    }

    if ProcessInfo.processInfo.environment["DISABLE_ANIMATIONS"] == "true" {
        // Отключаем анимации для стабильности тестов
        UIView.setAnimationsEnabled(false)
    }
    #endif

    // ...
}
--
