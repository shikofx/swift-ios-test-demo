В прошлом уроке мы научились находить элементы по их идентификатору. Но как `XCUITest` понимает, что мы ищем именно кнопку, а не текстовое поле? Это происходит благодаря системе запросов (`XCUIElementQuery`) и различным типам элементов.

Давайте подробно рассмотрим самые распространенные типы `XCUIElement`, с которыми вы будете сталкиваться.

== Что такое `XCUIElementQuery`?

Когда мы пишем `app.buttons`, мы не получаем массив всех кнопок на экране. Вместо этого мы создаем *запрос* (`XCUIElementQuery`), который "обещает" найти элементы, соответствующие определенным критериям, когда это потребуется.

Фактический поиск происходит только в тот момент, когда мы обращаемся к свойству элемента (например, `.exists`) или пытаемся выполнить с ним действие (например, `.tap()`). Это ленивый (lazy) механизм, который оптимизирует производительность тестов.

== Основные типы элементов и их запросы

Вот список наиболее часто используемых запросов к элементам:

=== `buttons`
*Описание:* Представляет кнопки (`UIButton`).
*Пример:* Поиск кнопки "Login" по ее тексту или идентификатору.

[source, swift]
--
let loginButtonByText = app.buttons["Login"]
let loginButtonById = app.buttons["Login button"]
--

=== `staticTexts`
*Описание:* Представляет нередактируемые текстовые метки (`UILabel`).
*Пример:* Поиск заголовка на экране.
[source, swift]
--
let productsHeader = app.staticTexts["Products"]
--

=== `textFields`
*Описание:* Представляет стандартные поля для ввода текста (`UITextField`).
*Пример:* Поиск поля для ввода имени пользователя.
[source, swift]
--
let usernameField = app.textFields["Username input"]
--

=== `secureTextFields`
*Описание:* Представляет поля для безопасного ввода текста, например, паролей (`UITextField` со свойством `isSecureTextEntry = true`).
*Пример:* Поиск поля для ввода пароля.
[source, swift]
--
let passwordField = app.secureTextFields["Password input"]
--

=== `images`
*Описание:* Представляет изображения (`UIImageView`).
*Пример:* Поиск изображения продукта.
[source, swift]
--
let productImage = app.images["Product image"]
--

=== `tables`, `collectionViews` и `cells`
*Описание:* Представляют таблицы, коллекции и их ячейки (`UITableView`, `UICollectionView`, `UITableViewCell`, `UICollectionViewCell`).
*Пример:* Поиск ячейки в таблице и элемента внутри нее.
[source, swift]
--
// Находим ячейку, содержащую текст "Sauce Labs Backpack"
let productCell = app.tables.cells.containing(.staticText, identifier: "Sauce Labs Backpack").element

// Теперь внутри этой ячейки можно найти другие элементы, например, кнопку "Add to cart"
let addToCartButton = productCell.buttons["Add to cart"]
--

=== `navigationBars`
*Описание:* Представляет навигационную панель вверху экрана (`UINavigationBar`). Полезно для поиска заголовка экрана или кнопок в панели.
*Пример:* Поиск кнопки "Корзина" в навигационной панели.
[source, swift]
--
let cartButton = app.navigationBars.buttons["Cart button"]
--

=== `alerts`
*Описание:* Представляет системные оповещения (`UIAlertController`).
*Пример:* Проверка появления алерта об ошибке и нажатие на кнопку "OK".
[source, swift]
--
let errorAlert = app.alerts["Error"]
XCTAssertTrue(errorAlert.waitForExistence(timeout: 2))
errorAlert.buttons["OK"].tap()
--

=== `switches`
*Описание:* Представляет переключатели (`UISwitch`).
*Пример:* Включение или выключение какой-либо опции.
[source, swift]
--
let notificationsSwitch = app.switches["Notifications switch"]
notificationsSwitch.tap() // Изменит значение на противоположное
--

=== `other` и `any`
*Описание:* `other` используется для поиска элементов, которые не подходят под стандартные типы (например, кастомные `UIView`). `any` используется для поиска любого элемента, независимо от его типа. Это "запасные" варианты, когда более конкретный тип не подходит.
*Пример:*
[source, swift]
--
// Поиск контейнера с определенным идентификатором
let mainContainer = app.otherElements["MainContainer"]
--

== Основные действия и проверки для `XCUIElement`

После того как мы нашли элемент, мы можем выполнять с ним различные действия и проверять его состояние. Вот самые полезные из них.

=== Проверка состояния (Verifications)

Эти свойства возвращают `Bool` и идеально подходят для использования в `XCTAssert`.

*   `.exists`: Проверяет, существует ли элемент в иерархии UI в данный момент. Это самая базовая проверка.
[source, swift]
--
XCTAssertTrue(app.buttons["Login"].exists)
--

*   `.isHittable`: Проверяет, является ли элемент "кликабельным" — то есть, существует ли он, виден ли на экране и не перекрыт ли другими элементами (например, клавиатурой или алертом).
[source, swift]
--
// Проверяем, что кнопка доступна для нажатия
XCTAssertTrue(app.buttons["Login"].isHittable)
--

=== Основные действия (Actions)

Эти методы имитируют жесты пользователя.

*   `.tap()`: Простое нажатие.
*   `.doubleTap()`: Двойное нажатие.
*   `.press(forDuration:)`: Длительное нажатие.

[source, swift]
--
// Удерживать кнопку в течение 2 секунд
app.buttons["Save"].press(forDuration: 2)
--

*   **Свайпы (Swipes):** `.swipeUp()`, `.swipeDown()`, `.swipeLeft()`, `.swipeRight()`. Эти методы имитируют жест свайпа по элементу. Чаще всего они используются для прокрутки экрана.

[source, swift]
--
// Прокрутить экран вниз, чтобы найти элемент, который не виден сразу
app.swipeUp()

// Смахнуть карточку влево
app.images["Product Card"].swipeLeft()
--

=== Получение данных из элемента

*   `.label`: Возвращает видимый текст элемента (то, что видит пользователь).
*   `.value`: Возвращает текущее значение элемента. Для текстового поля это будет введенный текст, для слайдера — его текущее числовое значение.
