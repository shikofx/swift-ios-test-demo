= Расширенная отчетность в Allure для UI-тестов (шаги, скриншоты)

В предыдущем уроке мы настроили запуск UI-тестов в CI и добавили их результаты в общий Allure-отчет. Однако для UI-тестов стандартного отчета часто бывает недостаточно. Когда тест падает, мы хотим знать не только *что* упало, но и *где* и *почему*.

В этом уроке мы значительно улучшим наши отчеты, добавив в них:

*   **Шаги (Steps):** Детальное описание действий, которые выполнял тест.
*   **Скриншоты при падении:** Визуальное представление экрана в момент сбоя.

== 1. Добавление шагов в отчет

Чтобы разбить выполнение теста на логические блоки, `XCTest` предоставляет мощный инструмент — `XCTContext.runActivity(named:...)`. Allure автоматически распознает эти блоки и отображает их в отчете как вложенные шаги.

Это идеальный инструмент для использования внутри наших Page Objects. Давайте отрефакторим метод `login` в `LoginPage`, чтобы он сообщал о своих действиях.

=== Рефакторинг `LoginPage`

Обернем каждое действие в `XCTContext.runActivity`.

[source, swift]
--
// LoginPage.swift

class LoginPage: BaseScreen {
    // ...
    // Actions
    @discardableResult
    func login(user: TestUser) -> ProductsPage {
        XCTContext.runActivity(named: "Ввод имени пользователя: \(user.username)") { _ in
            usernameTextField.clearAndTypeText(user.username)
        }

        XCTContext.runActivity(named: "Ввод пароля") { _ in
            // Мы не логируем сам пароль из соображений безопасности
            passwordTextField.clearAndTypeText(user.password)
        }

        // Баг: клавиатура не убирается.
        // app.keyboards.buttons["Return"].tap()

        XCTContext.runActivity(named: "Нажатие на кнопку 'Login'") { _ in
            loginButton.waitAndTap()
        }

        return ProductsPage(app: app)
    }
    // ...
}
--

Теперь, когда вы запустите тесты и сгенерируете отчет, в Allure вы увидите красивую иерархию шагов, которая точно описывает, что делал тест.

image::https://i.imgur.com/8E7aO1J.png[Пример шагов в Allure]

Проделайте аналогичный рефакторинг для других методов в ваших Page Objects (например, `openLoginScreen` в `MenuPage`).

== 2. Скриншоты при падении

Скриншот в момент падения UI-теста — это самый ценный артефакт для быстрой диагностики проблемы. Нам не нужно гадать, что пошло не так, — мы это видим.

Мы можем настроить автоматическое создание скриншотов для всех упавших тестов, добавив логику в наш базовый тестовый класс `BaseUITest`.

=== Рефакторинг `BaseUITest`

Мы переопределим метод `tearDown()`, который вызывается после каждого теста. В нем мы проверим, был ли тест успешным. Если нет — сделаем скриншот и прикрепим его к отчету.

[source, swift]
--
// BaseUITest.swift

import XCTest

class BaseUITest: XCTestCase {
    var app: XCUIApplication!

    override func setUp() {
        super.setUp()
        continueAfterFailure = false

        app = XCUIApplication()
        app.launchArguments.append("--reset")
        app.launch()
    }

    override func tearDown() {
        // Проверяем, не упал ли тест
        if testRun?.hasSucceeded == false {
            // Создаем скриншот
            let screenshot = XCUIScreen.main.screenshot()
            
            // Создаем вложение (attachment)
            let attachment = XCTAttachment(screenshot: screenshot)
            
            // Устанавливаем имя и время жизни
            attachment.name = "Screenshot on Failure"
            attachment.lifetime = .keepAlways // Сохранять всегда
            
            // Добавляем вложение к отчету
            add(attachment)
        }

        super.tearDown()
    }
}
--

Теперь, если какой-либо из наших UI-тестов упадет, в отчете Allure рядом с ошибкой появится скриншот, показывающий последнее состояние приложения.

image::https://i.imgur.com/T3fLqg1.png[Пример скриншота в Allure]

=== Как это работает?

1.  `testRun?.hasSucceeded == false`: `testRun` — это свойство `XCTestCase`, которое содержит информацию о текущем тестовом запуске. Мы проверяем его свойство `hasSucceeded`.
2.  `XCUIScreen.main.screenshot()`: Делает снимок всего экрана.
3.  `XCTAttachment`: Специальный класс для добавления вложений (файлов, скриншотов, данных) к результатам теста.
4.  `add(attachment)`: Метод `XCTestCase`, который прикрепляет вложение к текущему тесту.

Allure и другие инструменты для работы с `.xcresult` умеют находить эти вложения и отображать их в удобном виде.

== Что дальше?

Мы значительно повысили информативность наших отчетов. Теперь диагностика упавших UI-тестов будет занимать гораздо меньше времени.

Следуя нашей тестовой стратегии, мы уже покрыли Unit-тесты и сквозные UI-тесты. Настало время спуститься на один уровень пирамиды и заняться **Snapshot-тестами**, которые помогут нам защититься от визуальных регрессий.

== 3. Добавление видеозаписи всего теста

Иногда скриншота в момент падения недостаточно. Мы хотим видеть всю последовательность действий пользователя, которая привела к ошибке. Для этого можно настроить автоматическую видеозапись всего тестового прогона.

Эта настройка выполняется не в коде, а в **Test Plan**.

=== Настройка Test Plan

1.  Найдите в навигаторе проекта ваш файл `.xctestplan`. Если вы его не создавали, Xcode использует автосгенерированный. Чтобы его отредактировать, перейдите в `Product` -> `Test Plan` -> `Edit Test Plan...`.
2.  В открывшемся окне перейдите на вкладку **Configurations**.
3.  В секции **Test-Time Data** найдите опцию **Video Recording**.
4.  Измените ее значение с `On Failure` (По умолчанию) на `Always`.

image::https://i.imgur.com/gJvF8qH.png[Настройка видеозаписи в Test Plan]

=== Как это работает?

Теперь, когда вы запускаете UI-тесты (как локально, так и в CI через `xcodebuild`), система будет автоматически записывать видео для каждого теста и сохранять его в `.xcresult` бандл.

Инструмент для генерации Allure-отчета (`xcresults-allure-adaptor`) умеет находить эти видеозаписи и автоматически прикреплять их к соответствующим тестам в отчете. Никаких дополнительных изменений в коде или в CI-пайплайне не требуется!

В результате в вашем Allure-отчете рядом с каждым UI-тестом появится вложение с видео.

image::https://i.imgur.com/Y2h3b3k.png[Пример видео в Allure]

[TIP]
====
**Производительность**

Имейте в виду, что постоянная запись видео может незначительно замедлить выполнение тестов и увеличить размер артефактов (`.xcresult`). Поэтому для быстрых прогонов (например, в feature-ветках) можно использовать режим `On Failure`, а для релизных или ночных сборок — `Always`.
====
