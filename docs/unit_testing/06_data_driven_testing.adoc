== Теория

=== Что такое Data-Driven Testing?

*Data-Driven Testing (DDT)* — это подход, при котором одна и та же тестовая логика выполняется многократно с разными наборами входных и ожидаемых данных. Это позволяет эффективно тестировать множество сценариев, не дублируя код.

Представьте, что вы тестируете валидатор email. Вам нужно проверить десятки валидных и невалидных адресов. Вместо того чтобы писать десятки почти одинаковых тестов, вы можете написать один, который будет получать данные из внешнего источника.

=== Реализация в Swift

В отличие от некоторых других фреймворков (например, JUnit или NUnit), `XCTest` не имеет встроенной поддержки параметризации "из коробки". Однако это легко реализовать самостоятельно.

Самый простой способ — использовать цикл `for-in` внутри тестового метода.

[source,swift]
----
func test_EmailValidator_withVariousInputs() {
    // Given
    let validEmails = ["test@example.com", "user.name+tag@domain.co.uk"]
    let invalidEmails = ["test", "test@", "@domain.com", "test@domain..com"]
    let sut = EmailValidator()

    // When & Then
    for email in validEmails {
        XCTAssertTrue(sut.isValid(email), "Email '\(email)' должен быть валидным")
    }

    for email in invalidEmails {
        XCTAssertFalse(sut.isValid(email), "Email '\(email)' должен быть невалидным")
    }
}
----

*Преимущество:* Просто и быстро.
*Недостаток:* Если упадет один из кейсов в цикле, весь тест будет помечен как проваленный, и вы не увидите результаты для остальных данных в этом цикле. Для более сложных сценариев существуют сторонние библиотеки или более продвинутые кастомные решения, но для большинства случаев простого цикла достаточно.
