= Создание DSL для тестов (BDD) и интеграция с Allure
:source-highlighter: highlight.js

== Цель

Улучшить читаемость и структуру Swift-тестов, создав простой предметно-ориентированный язык (DSL) в стиле BDD (Behavior-Driven Development), и обеспечить его интеграцию с Allure Report.

---

== Проблема

Стандартные тесты в `XCTest` могут быть многословными и не всегда четко отражают структуру "Условие-Действие-Результат". Часто для этого используют комментарии:

[source,swift]
----
func testFeature_WithSomeCondition_ShouldProduceResult() {
    // Given: Начальные условия
    let a = 10
    let b = 20

    // When: Выполняется действие
    let result = a + b

    // Then: Проверяется результат
    XCTAssertEqual(result, 30)
}
----

Хотя это работает, такой подход не дает никаких преимуществ в отчетах и не группирует логические блоки в Xcode.

== Решение: `XCTContext.runActivity`

Фреймворк `XCTest` предоставляет мощный инструмент `XCTContext.runActivity`. Он позволяет группировать код в именованные блоки, которые отлично отображаются как в логах Xcode, так и в Allure-отчетах (при правильной настройке конвертера).

Чтобы сделать использование `runActivity` более удобным и декларативным, мы создадим `extension` для класса `XCTest`.

=== Реализация DSL

Создадим файл `XCTest+GivenWhenThen.swift` в тестовом таргете и добавим в него следующее расширение:

[source,swift]
----
import XCTest
 
extension XCTest {
    func given(_ desc: String, _ block: @MainActor (any XCTActivity) -> Void) {
        XCTContext.runActivity(named: "Given: \(desc)", block: block)
    }
 
    func when(_ desc: String, _ block: @MainActor (any XCTActivity) -> Void) {
        XCTContext.runActivity(named: "When: \(desc)", block: block)
    }
 
    func then(_ desc: String, _ block: @MainActor (any XCTActivity) -> Void) {
        XCTContext.runActivity(named: "Then: \(desc)", block: block)
    }
}
----

*   Мы создаем три функции: `given`, `when`, `then`.
*   Каждая из них принимает описание шага (`desc`) и блок кода (замыкание `block`).
*   Внутри они вызывают `XCTContext.runActivity`, добавляя префикс "Given:", "When:" или "Then:" для наглядности.

=== Использование

Теперь наши тесты становятся гораздо более читаемыми и структурированными.

[source,swift]
----
func test_calculateTotalPrice_when_cartIsEmpty_then_zero() {
    given("в корзине нет товаров") { _ in
        engine.cartList = []
    }
    
    when("рассчитывается общая стоимость") { _ in
        sut.calculateTotalPrice()
    }
    
    then("итоговая стоимость должна быть равна нулю") { _ in
        XCTAssertEqual(engine.totalPrice, 0.00)
        XCTAssertEqual(sut.totalPriceLbl.text, "$0.00")
    }
}
----

== Преимущества

*   **Читаемость:** Тесты читаются как обычный текст, что упрощает понимание их цели.
*   **Структура:** Четкое разделение на три логических блока.
*   **Отчетность:** Xcode и Allure будут отображать эти блоки как вложенные шаги, что очень помогает при анализе упавших тестов.

== Расширение DSL: Allure и обработка ошибок

Наш базовый DSL можно значительно улучшить, добавив две важные возможности: интеграцию с Allure и корректную обработку ошибок.

=== 1. Интеграция с Allure

Поскольку для Swift нет официальной библиотеки Allure, мы можем использовать "хитрый" трюк: передавать метаданные (epic, feature, story) через имена активностей `XCTActivity`. Инструмент `xcresults` специально обучен распознавать такие имена и преобразовывать их в теги Allure.

Добавим в наше расширение методы для установки тегов:

[source,swift]
----
extension XCTest {
    // ... (given, when, then)

    func epic(_ value: String) {
        label(name: "epic", value: value)
    }

    func feature(_ value: String) {
        label(name: "feature", value: value)
    }

    func story(_ value: String) {
        label(name: "story", value: value)
    }

    private func label(name: String, value: String) {
        // Создаем пустую активность со специальным именем
        XCTContext.runActivity(named: "allure.label.\(name):\(value)") { _ in }
    }
}
----

Теперь в тесте можно просто написать `epic("Авторизация")`, и в отчете Allure появится соответствующий тег.

=== 2. Поддержка `async/await` и обработки ошибок

Современный Swift активно использует асинхронный код. Чтобы наш DSL поддерживал `async/await` и мог "пробрасывать" ошибки из тестовых блоков, нужно обновить сигнатуры функций.

Вот как выглядит финальная, более мощная версия нашего DSL:

[source,swift]
----
import XCTest

extension XCTest {
    // Асинхронные версии с поддержкой ошибок
    func given(_ desc: String, _ block: @MainActor (any XCTActivity) async throws -> Void) async rethrows {
        try await XCTContext.runActivity(named: "Given: \(desc)", block: block)
    }

    func when(_ desc: String, _ block: @MainActor (any XCTActivity) async throws -> Void) async rethrows {
        try await XCTContext.runActivity(named: "When: \(desc)", block: block)
    }

    func then(_ desc: String, _ block: @MainActor (any XCTActivity) async throws -> Void) async rethrows {
        try await XCTContext.runActivity(named: "Then: \(desc)", block: block)
    }
    
    // ... (методы для Allure)
}
----

*   `async`: Позволяет использовать `await` внутри блоков `given/when/then`.
*   `throws` / `rethrows`: Позволяет писать "бросающие" функции внутри блоков и корректно обрабатывать падение теста, если возникла ошибка.
